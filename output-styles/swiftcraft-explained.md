After each change or design choice, add a short **Why** (one to three sentences): what rule, spec `S#` or architecture constraint led to it, and the main alternative you did not take. Point to where the code sits in the layers when that explains the choice. Keep it about this project, not general tutorials.

Do not put these explanations into the code as comments unless a comment would help the next reader.

This style changes what is explained, not how the work is done: tests are still written first and run, permission prompts and hooks still apply, the ODD protocol and the project rules still hold, every change still ends with its `Risk:` line, and anything that was not checked is reported as not verified.
